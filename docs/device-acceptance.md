# Android 실기기 인수 확인

**실행 상태: 실기기 테스트 미실행.** 연결된 휴대폰이 없으므로 아래 항목은 전부 `NOT_RUN`이다. APK 빌드 성공, 모델 렌더, 코드 검토, 증거 수집 성공을 실제 AR 작동의 증명으로 간주하지 않는다. 사용자가 GitHub Release APK를 설치한 뒤 직접 확인한다.

## 준비와 설치

1. Release에서 `ar-dogy-<version>-dev.apk`, `SHA256SUMS.txt`, `build-info.json`을 다운로드한다. APK SHA256, 버전, 커밋을 기록한다. PowerShell에서 `Get-FileHash .\ar-dogy-<version>-dev.apk -Algorithm SHA256`의 값을 비교한다.
2. Android 7.0/API 24 이상 기기에서 APK를 열어 설치한다. 앱 패키지는 `com.im6705.ardogy`이다. 기기와 Google Play Services for AR의 지원 여부는 실제 앱 흐름으로 확인한다. AR 미지원 기기에서는 산책 기능을 검증할 수 없다.
3. 이 APK는 개발용 서명이다. 이전 앱과 서명이 다르면 Android가 업데이트를 거부할 수 있다. 데이터를 지우거나 기존 앱을 제거하는 작업은 이 문서나 증거 스크립트가 자동 수행하지 않는다.
4. 밝고 무늬가 있는 넓은 실제 바닥을 준비한다. 주변 사람, 문서, 화면 등 개인정보가 카메라에 들어오지 않게 한다. 인식된 평면은 장애물 지도가 아니므로 가구나 계단 회피를 기대하지 않는다.

## 직접 수행할 E2E 항목

각 항목에 `PASS / FAIL / NOT_RUN / NOT_APPLICABLE`과 실제 관찰, 시각, 증거 파일명을 남긴다. `NOT_APPLICABLE`에는 사유가 필요하며 전체 기기 호환성을 입증하지 않는다.

| ID | 사용자 동작 | 기대 결과 / 확인할 실패 |
| --- | --- | --- |
| INSTALL | APK 설치 후 앱 아이콘으로 실행한다. | 앱이 열리고 크래시하지 않는다. 설치한 버전과 릴리스 APK가 일치한다. |
| CAMERA_DENY | 첫 카메라 요청을 거절한다. | 검은 화면에 갇히거나 크래시하지 않고 카메라 필요 안내와 `카메라 허용하기` 경로가 보인다. 카메라 없이 AR가 실행된 것처럼 표시하지 않는다. |
| CAMERA_GRANT | 안내에서 다시 권한 요청 후 허용한다. | 카메라 영상과 바닥 인식 흐름으로 진입한다. `바닥을 천천히 비춰 주세요`가 표시된다. |
| CAMERA_PERMANENT_DENY | OS에서 재요청이 차단될 때까지 거절하거나 설정에서 권한을 차단한다. 앱의 설정 안내를 따라 권한을 허용하고 돌아온다. | 반복 권한 팝업 루프 없이 설정 복구 경로가 있다. 앱 복귀 후 권한을 다시 확인하여 AR로 진입한다. Android 버전에 따라 거절 횟수와 문구가 다르다. |
| AR_SERVICE | AR 서비스 설치/업데이트가 필요한 기기에서 앱을 실행한다. 요청을 취소한 뒤 다시 시도하고, 설치 완료 후 복귀한다. | 실제 Google/ARCore 설치 흐름으로 안내한다. 취소·네트워크 문제·서비스 문제를 성공으로 표시하지 않는다. 설치 후 재시도할 수 있다. 서비스가 이미 최신이면 이 경로는 미실행으로 남긴다. |
| UNSUPPORTED_DEVICE | 가능하다면 AR 미지원 기기에서 실행한다. | 지원 불가 안내가 표시되고 산책 화면을 성공 상태로 꾸미지 않는다. 지원 기기 한 대에서 이 항목을 통과 처리하지 않는다. |
| FLOOR_PLACE | 실제 수평 바닥을 천천히 여러 각도에서 비춘다. `바닥을 터치해 주세요` 이후 충분히 넓은 바닥의 중앙을 터치한다. 벽·화면 빈 곳도 터치한다. | 적합한 바닥에서만 도기 한 마리가 배치된다. 원본 털·얼굴·눈·질감이 보이고 발이 바닥 높이에 맞는다. 벽이나 미인식 공간에 배치되지 않는다. |
| WALK_IDLE | 배치 후 약 60초간 폰을 조금 이동하며 관찰한다. | 도기가 바닥 위에서 실제 이동하고 다리 관절의 `Walk` 동작이 반복된다. 휴식 시 `Idle` 동작으로 바뀐다. 모델 전체만 미끄러지거나 다리가 고정된 이동은 실패다. 몸이 뒤집히거나 바닥을 뚫지 않는다. |
| PAUSE_RESUME | 걷는 중 `잠깐 쉬기`를 누르고 약 10초 뒤 `다시 걷기`를 누른다. | 휴식 중 위치가 고정되고 휴식 동작이 보인다. 재개하면 걷기를 계속한다. 연타해도 복제되거나 튀지 않는다. |
| RESET | `다시 배치`를 누르고 다른 바닥 지점을 선택한다. | 기존 도기가 제거되고 바닥 선택 흐름으로 돌아온다. 새 위치에 한 마리만 생성되고 정상적으로 걷는다. |
| TRACKING_LOSS | 걷는 중 렌즈를 가리거나 무늬 없는 곳을 잠시 비추고 원래 바닥으로 돌아온다. | 추적 손실 중 `주변을 다시 확인하고 있어요`와 함께 이동·애니메이션이 멈춘다. 복구 시 큰 시간 점프 없이 재개한다. 추적 불가 상태로 계속 걷는 것은 실패다. |
| BACKGROUND_RESUME | 걷는 중 홈 화면으로 나가 10초 후 앱으로 복귀한다. 화면 잠금/해제도 별도 확인한다. 휴식 상태에서도 반복한다. | 카메라·AR 세션이 정상 복귀한다. 배경에 있던 시간만큼 위치가 순간 이동하지 않는다. 사용자가 정한 휴식 상태를 유지한다. 크래시·중복 모델·카메라 점유 오류가 없다. |
| PLANE_MERGE | 같은 바닥의 떨어진 두 영역을 인식한 뒤 중간 영역도 천천히 스캔해 평면이 확장·병합되는 상황을 관찰한다. | 도기가 복제되거나 사라지지 않고 현재 추적되는 바닥 안에서 계속 움직인다. 병합이 실제 관찰되지 않았다면 `NOT_RUN`으로 기록한다. |
| PLANE_EDGE | 좁게 인식된 바닥의 가장자리를 터치한 뒤, 넓게 스캔하여 다시 중앙에 배치한다. 움직임을 60초 관찰한다. | 몸체 여유 공간이 부족하면 배치를 거부하거나 `조금 더 넓은 바닥이 필요해요`로 멈춘다. 충분한 공간에서는 안전 여백을 두고 평면 안에서 움직인다. 바닥을 잃으면 안내와 재배치 경로가 있다. 인식된 경계와 물리적 가구 경계를 혼동하지 않는다. |

스틸 스크린샷 한 장으로 걷기·정지·복귀·평면 병합을 증명할 수 없다. 해당 항목은 직접 시간 경과를 관찰하고 기록하며, 필요하면 사용자가 OS 화면 녹화로 실제 앱 흐름을 남긴다. 권한 팝업이나 설정 화면 증거는 사용자가 직접 기록한다. 아래 스크립트는 앱이 전경이 아니면 캡처를 거부한다.

## 선택 사항: 반복 가능한 증거 수집

Windows PowerShell 5.1 이상과 Android SDK platform-tools의 `adb`가 필요하다. USB 디버깅 연결을 사용자가 직접 허용한다. 스크립트는 설치·삭제·권한 변경·앱 실행·로그 초기화·터치·화면 녹화를 수행하지 않는다.

앱을 **전체 화면의 전경**에 두고 권한 팝업·알림창을 닫는다. 카메라에 개인정보가 없는지 확인한 다음 실행한다. 아래 버전/코드/SHA/커밋은 다운로드한 `build-info.json`과 `SHA256SUMS.txt`의 실제 값으로 바꾼다.

```powershell
adb devices
.\scripts\capture-device-evidence.ps1 `
  -Serial 'YOUR_DEVICE_SERIAL' `
  -ApkPath '.\ar-dogy-0.1.0-dev.apk' `
  -ExpectedVersionName '0.1.0' `
  -ExpectedVersionCode 123 `
  -ExpectedApkSha256 'REPLACE_WITH_64_HEX_CHARACTERS' `
  -ExpectedCommit 'REPLACE_WITH_40_HEX_CHARACTERS' `
  -CaseId 'WALK_IDLE'
```

연결 기기가 정확히 한 대일 때만 `-Serial`을 생략할 수 있다. `-AdbPath 'C:\Android\platform-tools\adb.exe'`로 adb 위치를 지정할 수 있다. `-ExpectedApkSha256`과 `-ExpectedCommit`은 선택 인수이며 입력할 때 형식과 값을 정확히 맞춘다. 버전 이름과 코드는 필수다.

수집 결과는 기본적으로 저장소의 `work/device-evidence/<UTC>-<CaseId>-<id>/`에 생성된다. 다른 폴더는 `-OutputDirectory`로 지정한다.

- `metadata.json`: 패키지/설치 버전, 로컬·설치 APK SHA256 일치, 기기 제조사·모델·OS, 시각. 기기 시리얼은 해시만 저장한다. 커밋은 사용자가 제공한 릴리스 참조이며 APK에서 독립 검증한 값이 아니다. 릴리스 `build-info.json`과 따로 대조한다.
- `screenshot.png`: 대상 앱이 resumed activity와 focused window인지 전후 확인한 PNG. 다른 앱·시스템 창이 전경이면 거부하며 기기 데이터는 바꾸지 않는다. 캡처 동안 다른 앱으로 전환하거나 알림을 열지 않는다.
- `logcat-app.txt`: 현재 앱 PID만, 최대 기본 600줄. `logcat-system-target.txt`: 지정된 시스템 태그 중 대상 패키지 이름이 명시된 줄만. 과거 크래시나 사라진 프로세스의 로그 전체를 수집하지 않으므로 빈 로그가 정상 동작의 증명은 아니다.
- `acceptance-results.csv`: 모든 항목을 `NOT_RUN`으로 시작한다. 직접 실행한 항목의 실제 결과와 증거 경로를 작성한다. 캡처를 여러 번 실행하면 별도 폴더가 만들어져 이전 관찰을 덮어쓰지 않는다.

스크립트는 설치된 단일 APK의 SHA256이 지정한 로컬 APK와 다르면 중단한다. 분할 APK 설치는 이 절차 범위 밖이다. 수집 전에 버전/전경 상태 검사에 실패하면 앱으로 돌아가 조건을 해결한 뒤 다시 실행한다. 일부 증거 수집이 실패한 폴더를 완성된 테스트 결과로 공유하지 않는다. 공유 전 카메라 화면과 로그를 직접 검토한다.

실패 보고에는 기기 모델/Android, Release 버전·APK SHA·커밋 참조, 항목 ID, 재현 순서, 예상 결과, 실제 결과, 증거 파일명을 포함한다. 직접 수행하지 못한 항목은 완료로 바꾸지 않는다.
